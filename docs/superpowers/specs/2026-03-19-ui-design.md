# PLND UI Design Spec
**Date:** 2026-03-19
**Status:** Approved

---

## Context

PLND is a neurodivergent-focused planner for nutrition, exercise, and daily planning. The UI must reduce cognitive load, preserve spatial context, and avoid the anxiety of rigid scheduling or overwhelming catalogs. Phase 2.5 establishes the visual design system and core interaction model before feature work resumes.

---

## Design Philosophy

**Primary theme:** Warm & Encouraging — amber and gold tones, supportive and personal, like a trusted journal.
**Dark mode:** Structured & Sharp — dark backgrounds, high contrast, grid-precise. Same structure as light mode, different mood.
**Core principle:** The daily schedule IS the app. Everything else is peripheral. Neurodivergent-friendly design means preserving spatial context, avoiding catalog anxiety, and keeping friction low.

## Typography

- **Font family:** `system-ui, -apple-system, sans-serif` (no web font dependency)
- **Meal name:** `14px`, `font-weight: 800`, `color: text-primary`
- **Row text:** `12px`, `font-weight: 400`, `color: text-body`
- **Time gutter:** `10px`, `font-weight: 600`, `color: text-secondary`
- **Section badges (TODAY, Done):** `9px`, `font-weight: 700`, `letter-spacing: 0.08em`, uppercase
- **Date header:** `15px`, `font-weight: 800`, `color: text-primary`

## Navigation

### Responsive strategy
- **Desktop (≥ 768px):** Collapsible icon sidebar, 52px wide by default. Icons only; expands to labels on hover or toggle. When expanded, the sidebar **overlays** the content area (does not push/reflow the row grid) — this minimises layout shift, which is important for users sensitive to sudden reflow.
- **Mobile (< 768px):** Bottom tab bar, thumb-friendly.

### Touch targets (mobile)
All interactive elements on mobile must have a minimum **44×44px tap target**, even if the visual element is smaller. Implement via padding or `::after` pseudo-element extension. This applies to: checkboxes, meal band tap zones (`Plan ›`, `Done`), date nav pill buttons, and avatar dropdown trigger.

### Nav items
The sidebar/tab bar contains **only one primary item: Today (📅)**. All core workflows originate from the daily schedule view. Profile, Settings, and Dietary Restrictions are reached via the user avatar dropdown (top-right of the navbar), not the sidebar.

### Date navigation
The day header contains:
- **‹** and **›** amber pill buttons (background: `accent-light`, border: `accent-border`) to step prev/next day
- A centred date label (`Thursday, Mar 19`) with a `TODAY` badge beneath the current date
- Tapping the date opens a calendar picker for arbitrary day navigation

## Daily Schedule View

The primary and near-exclusive screen of the app. All task/meal/exercise interactions happen in-context — no page navigation for core workflows.

### Row grid

All rows share a fixed column layout:

```
24px left-pad | 40px gutter | 12px gap | 16px checkbox | 10px gap | flex text
```

- **Meal rows:** emoji (20px) centred in the 40px gutter; no checkbox; full-width amber band
- **Timed items:** time string (`11 AM`) centred in gutter; checkbox to the right; time in `text-secondary`
- **Untimed items:** gutter empty; checkbox to the right; text in `text-body`

### Meal bands

Meals are the structural anchors of the day. They render as a full-width amber band:

- Background: `surface-meal`
- Top and bottom border: `1.5px solid border-meal`
- Padding: `12px 24px`
- Meal name: `14px / 800` in `text-primary`
- Description (dish name): `11px` in `text-secondary`, inline after the name
- Status badge: `Done` (amber, filled) or `Plan ›` (amber, bordered, tappable)
- Future meals (not yet reached): `opacity: 0.45`

### During-meal tasks

Tasks anchored to a specific meal (e.g. vitamins, reading) live **inside the meal band**, below the meal header, separated by a faint sub-divider (`1px solid rgba(border-meal, 0.5)`). They follow the standard row grid (empty gutter, checkbox, text) but inherit the amber band background. Checkbox border uses `accent-dark` rather than `border-row`.

### Task / appointment rows

- Background: `surface-white`
- Bottom border: `1px solid border-row`
- Padding: `10px 24px`
- **Checkbox (unchecked):** `16×16px`, `border-radius: 4px`, `2px solid border-row`
- **Checkbox (checked):** amber fill (`accent-light`), amber border (`accent`), amber SVG checkmark; text is struck through at `opacity: 0.45`

### "Add something…" row

Sits at the bottom of each day's list. Dashed border checkbox, muted text, `opacity: 0.5`. Tapping opens the natural language entry bar (see below).

### Empty day state

When a day has no items at all (no meals, tasks, or appointments), display a single centred message in `text-muted` below the date header:

> *"Nothing planned yet. Add something to get started."*

The message is followed by a prominent amber `+ Add something` button (using the same pill button pattern as date nav). Tone is neutral and inviting — not performative. No illustrations required.

### Loading states

When day data is being fetched (initial load or date navigation):
- Date nav arrows are disabled and reduced to `opacity: 0.4`
- The schedule list area shows **3 skeleton rows**: full-width bars at `surface-warm` with `opacity: 0.4`, animated with a gentle left-to-right shimmer pulse (`1.4s ease-in-out infinite`). One skeleton row is meal-band height; two are task-row height.
- Skeleton resolves to real content when the fetch completes; no flash if response is < 150ms.

### Error states

| Scenario | Treatment |
|---|---|
| Day data load failure | Inline message centred in the schedule area: *"Couldn't load your day. Tap to retry."* in `text-muted`, with a small amber retry link. No red banners — tone stays calm. |
| Optimistic check-off reversal | Row briefly flashes a `destructive`-tinted background (`rgba(destructive, 0.08)`) for 400ms, then reverts to unchecked state. No toast. |
| NL entry parse failure | Entry bar shows `text-muted` hint below the input: *"Not sure what to add — try 'walk after lunch' or 'vitamins with breakfast'."* Input remains focused. |

## Natural Language Entry ("Add something…")

The primary creation surface. A free-form text input appears in-context (bottom sheet on mobile, inline panel on desktop).

- The user types naturally: `"vitamins with breakfast"`, `"30 min walk after lunch"`, `"dentist Friday 2pm"`
- The app parses intent on the fly and resolves to the appropriate type (task, meal, exercise, appointment)
- If the resolved type requires structured data, a small supplementary form fades in **below** the text input (`150ms ease-out`). Common cases:
  - **Appointment:** time picker + optional location field
  - **Exercise:** duration field + optional intensity selector
- The LLM is the primary resolver; structured parsing is a fast-path for common patterns
- On **desktop:** entry bar appears as an inline panel anchored above the "Add something…" row, expanding downward
- On **mobile:** entry bar opens as a bottom sheet with the keyboard raised; supplementary fields appear above the keyboard

## In-Context Interactions

Core interactions never navigate away from the schedule view:

| Action | Pattern |
|---|---|
| View task/meal detail | Slide-in panel (desktop) / bottom sheet (mobile) |
| Quick inline edit | Inline expansion within the row |
| Complex edit (appointment, meal planning) | Bottom sheet with structured form |
| Add item | Natural language entry bar (see above) |
| Check off item | Tap checkbox — immediate optimistic update |

Page navigation is reserved for infrequent administrative screens: Profile, Settings, Dietary Restrictions (all reached via avatar dropdown).

## Accessibility

- **Contrast target:** WCAG AA minimum across all text/background combinations. The `text-secondary` (`#b45309`) on `surface-meal` (`#fffbf0`) pair is the tightest combination — confirmed passing at 4.6:1.
- **Focus rings:** `2px solid accent` with `outline-offset: 2px` on all interactive elements. In dark mode, use `accent` (`#6366f1`). Never remove outlines; the `focus-visible` pseudo-class may be used to suppress rings on pointer interaction only.
- **ARIA labels:** Checkboxes require `aria-label` describing the item (e.g. `"Mark 'Morning vitamins' as complete"`). Date nav buttons: `aria-label="Previous day"` / `"Next day"`. Meal status badges are non-interactive; mark `aria-hidden="true"`.
- **Keyboard navigation:** Tab order follows visual document order (top to bottom). The date nav header is reachable before the schedule list. Checkbox activation via `Space`; meal band expansion via `Enter`.

---

## Dark Mode Implementation

Dark mode maps all colour tokens to the dark palette (see Colour Tokens above). The structural layout — gutter column, meal bands, row dividers — is identical. The mood shifts from warm amber to cool indigo. The `prefers-color-scheme` media query drives the default; the user's stored theme preference overrides it (already implemented in preferences API).
